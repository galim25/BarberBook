# ERD: BarberBook — מערכת ניהול תורים למספרה

> **עודכן 2026-10-06** מול `packages/db/prisma/schema.prisma` (מקור האמת לסכימה) ומול כל ה-migrations עד `20261006120000_add_waitlist_notify_freed_slots`. הגרסה הקודמת נשמרה ב-`docs/archive/ERD BarberBook.txt.bak-2026-10-06`.
>
> **מה נוסף מאז הגרסה הקודמת:** ישויות `Barber`, `PushSubscription`, `LoginCode`, `ContactName`; שדות `Service.is_child_service`/`is_manual_only`, `WorkDay.barber_id`/`is_blocked`, `Appointment.booked_via_ivr`, `AppSettings.ivr_enabled`, `WaitlistEntry.notify_freed_slots`; שלושה ערכי `NotificationType` (`booking_request_pending`, `cancellation_request_pending`, `customer_registered`); enum `ContactNameSource`.

## 1. Overview

המודל מתאר מערכת תפעולית לניהול לקוחות, שירותים, ימי עבודה ותורים עבור ספר עצמאי (עם אפשרות לספרי משנה). מוקד המודל הוא זמינות מבוססת ימי עבודה, הפסקות ושעות חסומות, לצד תהליך קביעת תור, שינוי תור, בקשת ביטול ושליחת הודעות ללקוחות (in-app ו-Web Push).

המודל תומך גם בתורים שנקבעים עבור ילדים, בתורים ידניים שאינם בהכרח מקושרים לחשבון לקוח רשום, בתורים שנקבעו בטלפון (IVR), בכניסה של לקוחות עם קוד SMS חד-פעמי, ובשמות אנשי קשר פרטיים של הספר.

### LoginCode

**Purpose:** קוד כניסה חד-פעמי ב-SMS (`CUSTOMER_LOGIN_MODE="sms_code"`, ראו `docs/SMS-LOGIN.md`). מפותח לפי מספר טלפון ולא לפי `User`, כי לקוח חדש עדיין אין לו שורת `User`.

**Source:** תוספת מעבר ל-PRD (2026-09-22, migration `add_login_codes`).

| Field        | Type     | Required | Notes |
| ------------ | -------- | -------- | ----- |
| id           | string   | yes      | Primary key |
| phone_number | string   | yes      | ללא FK. Index משולב `(phone_number, created_at)` |
| code_hash    | string   | yes      | HMAC-SHA256 (מפתח `SESSION_SECRET`) — **הקוד עצמו לעולם לא נשמר** |
| expires_at   | datetime | yes      | תוקף `LOGIN_CODE_TTL_MINUTES` = 10; index |
| attempts     | integer  | yes      | ברירת מחדל 0; `LOGIN_CODE_MAX_ATTEMPTS` = 5 ניחושים שגויים ואז הקוד נשרף |
| consumed_at  | datetime | no       | מועד שימוש (חד-פעמי); קוד חדש מבטל ישנים |
| created_at   | datetime | yes      | Set at creation |

ה-worker מוחק קודים שפג תוקפם מעל יממה (cron יומי 03:17).

**שירותי הקטלוג (לפי ה־PRD):**

| Service          | Duration | הערות |
| ---------------- | -------- | ----- |
| תספורת מבוגר     | 10 דקות  | מוצע גם לספר-משנה ובטלפון |
| תספורת + זקן     | 15 דקות  | מוצע גם לספר-משנה ובטלפון |
| תספורת ילד       | 10 דקות  | `is_child_service = true`; מוצע גם לספר-משנה ובטלפון |
| הסרת שיער בלייזר | 10 דקות  | ספר ראשי בלבד |
| חלאקה            | 15 דקות  | ספר ראשי בלבד |
| תספורת מבוגר + טיפול לייזר | 20 דקות | ספר ראשי בלבד |

**שירותים מוסתרים לתור ידני** (`is_manual_only = true`):

| Service        | Duration |
| -------------- | -------- |
| תור ידני 5 דק' | 5 דקות   |
| תור ידני 10 דק' | 10 דקות |
| תור ידני 15 דק' | 15 דקות |

הספר קובע תור ידני בלי לבחור שירות — רק שם + משך; כל משך ממופה לשירות המוסתר המתאים כדי ש-`Appointment.service_id` יישאר חובה וכל חישובי `ends_at`/העברה ימשיכו לעבוד.

| id                  | string                                | yes      | Primary key                                                 |
| appointment_id      | reference: Appointment                | yes      | **ייחודי** — לכל תור בקשה אחת לכל היותר                    |
| status              | enum: [pending, approved, rejected]   | yes      | מצב הבקשה; ברירת מחדל `pending`                            |

**הערת מודל חשובה:** ה-`Appointment` הנלווה נוצר מיד עם הבקשה (status `scheduled`) ותופס את השעה ביומן — הבקשה אינה "רק כוונה", אלא ריזרווציה בפועל. דחיית הבקשה משנה את `Appointment.status` ל-`cancelled` ומשחררת את השעה; אישור לא משנה את התור כלל.

**מחיקה במקום סטטוס:** כשלקוח מבטל תור בזמן שהבקשה עדיין `pending` (מותר מ-2026-10-05), הביטול מיידי בלי אישור ספר והשורה **נמחקת** (`deleteMany` מותנה ב-`pending`) — אין סטטוס `withdrawn` ב-enum.

### Notification

**Purpose:** מייצגת הודעה in-app (פיד + badge) ללקוח או למנהל בנוגע לתזכורת, שינוי תור, החלטה בבקשת ביטול/תור, תור חדש שנקבע, בקשות ממתינות, לקוח חדש, או התפנות/הרחבת זמינות לרשימת המתנה. ההודעה ממומשת גם כ-Web Push (ראו `PushSubscription`) — אך לא כל Push יוצר שורה (למשל הודעה כללית).

**Source:** US-007, US-008, US-009, US-016, US-019, US-020, US-021, US-024, US-025

**הערת מודל:** אין `booking_request_id` נפרד — הודעת `booking_decision` מצביעה על `appointment_id` בלבד. `appointment_id`/`cancellation_request_id` נשארים `null` כשמדובר במחיקה קשה (הרשומה לא שורדת).

| Field                   | Type                           | Required | Notes                   |
| ----------------------- | ------------------------------ | -------- | ----------------------- |
| id                      | string                         | yes      | Primary key             |
| user_id                 | reference: User                | yes      | מקבל ההודעה — לקוח או מנהל (index) |
| appointment_id          | reference: Appointment         | no       | התור הרלוונטי להודעה    |
| cancellation_request_id | reference: CancellationRequest | no       | בקשת הביטול הרלוונטית   |
| type                    | enum: NotificationType (9 ערכים — ראו סעיף 3) | yes | סוג ההודעה |
| content                 | text                           | yes      | תוכן ההודעה             |
| status                  | enum: [pending, sent, failed]  | yes      | מצב השליחה; ברירת מחדל `pending` |
| scheduled_at            | datetime                       | no       | מועד השליחה המתוכנן     |
| sent_at                 | datetime                       | no       | מועד השליחה בפועל       |
| read_at                 | datetime                       | no       | מועד קריאה — בשימוש להתראות מנהל; ה-badge ב-`/admin` סופר `read_at IS NULL`; "סמן הכל כנקרא" (אין סימון פר-שורה) |
| created_at              | datetime                       | yes      | Set at creation         |

Indexes: `(user_id)`, `(status, scheduled_at)`.

**שימוש לפי סוג:**

|---|---|---|

| `waitlist_slot_available` | לקוח ברשימת המתנה | תור שהתפנה (רק עם `notify_freed_slots`), הרחבת שעות, יום חדש |

## 8. Open Questions / Design Notes

* ה־PRD אינו דורש ניהול פרופילים קבועים לילדים. לכן פרטי הילד נשמרים ברמת התור באמצעות `attendee_name` ו־`attendee_type`, ללא ישות `Child` נפרדת.
* ה־PRD מציין מחיקה של תורים ויומנים ללא אפשרות שחזור. לכן המודל מניח מחיקה מלאה (hard delete, cascade) ולא שמירה בארכיון. **ביטול תור בודד** הוא soft (`status = cancelled`); **מחיקת יום/יומן/ספר** היא hard; **חסימת יום** (`is_blocked`) לא מוחקת כלום.
* אין סטטוס "הסתיים" לתור — תור היסטורי נשאר `scheduled`. לכן כל לוגיקה שמטפלת בתורי עבר חייבת לבדוק גם `starts_at >= now`.
* המודל מניח שלכל תור יכולה להיות בקשת ביטול אחת בלבד (`appointment_id` ייחודי): בקשה שנדחתה חוזרת ל-`pending` בבקשה נוספת ולא נוצרת שורה חדשה.
* `AppSettings` הוא סינגלטון בכוונה (PK קבוע `"singleton"`) ולא טבלת key-value כללית. הגדרות גלובליות נוספות = עמודות נוספות באותה שורה.
* `WaitlistEntry` כללי במכוון (לא לפי תאריך/שירות): לקוח מקבל הודעה על כל התפנות/פתיחה, לא רק על מה שרלוונטי לו ספציפית. `AppSettings.requires_approval` ו-`WaitlistEntry` אינם מודעים-לספר — נשארו גלובליים בכוונה.
* `Barber` אינה `User`: ספרי משנה אין להם כניסה. כל ההרשאות נשארות אצל חשבון ה-administrator היחיד.
* `LoginCode` ו-`ContactName` מפותחים לפי מספר טלפון ללא FK — בכוונה (ראו הסברים בישויות).
